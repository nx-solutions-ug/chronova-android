# CI/CD & Automation

All continuous integration, dependency updates, issue/PR triage, and release
plumbing lives in `.github/`. The wiki update pipeline is also driven from
here. This section documents every moving part so contributors and agents
can reason about what each workflow does before they touch it.

## Workflows at a glance

| Workflow | Trigger | Purpose |
|----------|---------|---------|
| [`build.yml`](./workflows.md#buildyml) | Manual (`workflow_dispatch`) | Runs unit tests, builds debug + release APKs, uploads artifacts. |
| [`omp-ci.yml`](./omp-agent.md#omp-ciyml) | Issues opened; PRs opened / synchronize / ready_for_review; manual dispatch | Triage issues, label PRs, review PRs with the OMP agent. |
| [`omp.yml`](./omp-agent.md#ompyaml) | Issue / PR comments containing `/omp` | On-demand agent runs that expand `.omp/commands/*.md` templates. |
| [`omp-fix-issue.yml`](./omp-agent.md#omp-fix-issueyml) | `repository_dispatch` (`issue-triaged`) | Agent-driven follow-up to a triaged issue. |
| [`update-wiki.yml`](./wiki-pipeline.md) | Push to `main`, daily schedule, manual dispatch | Rebuilds this wiki, opens a staging PR, and publishes to the GitHub wiki repo. |
| [`vouch-pr.yml`](./vouch-system.md#vouch-pryml) | PR opened / reopened / ready_for_review | Closes PRs from unvouched authors and labels vouched PRs. |
| [`vouch-manage.yml`](./vouch-system.md#vouch-manageyml) | Discussion comments containing `!vouch`, `!denounce`, `!unvouch` | Maintainers manage the vouched list. |
| [`auto-manage.yml`](./workflows.md#auto-manageyml) | Issues opened / reopened; PRs opened | Tags `needs-triage`, auto-assigns to `niklasschaeffer`. |

All workflows authenticate with a GitHub App via
`actions/create-github-app-token` (id `APP_CLIENT_ID` + `APP_PRIVATE_KEY`),
not the default `GITHUB_TOKEN`. This scopes the token to the repository.

## Release Drafter

`.github/release-drafter.yml` aggregates merged PRs into the next release
notes. Categories are derived from labels:

| Category | Trigger labels |
|----------|----------------|
| 🚀 Features | `feature`, `enhancement` |
| 🐛 Bug Fixes | `bug`, `fix` |
| 🧰 Maintenance | `chore`, `docs`, `documentation` |
| 🔄 Dependencies | `renovatebot` |

Version bumps follow the labels attached to the merged PRs: `priority: critical`
forces a major bump; `feature`/`enhancement` force a minor bump; everything
else is a patch.

## Renovate

`renovate.json` configures Renovate to keep dependencies current. It opens
PRs for `actions/*`, `gradle/wrapper/*`, Gradle plugins, and AndroidX
libraries. Renovate PRs are routed through the OMP `label-pr` and
`review-pr` jobs but skip re-review on `synchronize` (the
`re-review-check` step only fires for non-agent commits).

## OMP agent

The "OMP" agent is the project's automated reviewer / triager. See
[OMP Agent](./omp-agent.md) for command templates, model selection, and
how the agent commits its own follow-up PRs.

## Vouch system

External contributors must be vouched before a PR can land. See
[Vouch System](./vouch-system.md) for the workflow and the maintainer
commands. Write access collaborators and bot accounts are exempt.

## Wiki pipeline

The wiki is generated by a separate `wiki-agent` tool and published to
the GitHub wiki repo. See [Wiki Pipeline](./wiki-pipeline.md) for the
flow and how staging PRs are produced.

## What is **not** automated

- **Tests**: `app/src/test/` and `app/src/androidTest/` are empty. The
  build workflow runs `testDebugUnitTest`, which is a no-op until tests
  are added.
- **Static analysis**: no ktlint, detekt, or custom `lint.xml` is
  configured. Default Android lint applies.
- **Signing credentials**: the release keystore is committed to the repo
  and the passwords are hardcoded in `app/build.gradle` for convenience.
  Treat this as a known limitation, not a workflow.
